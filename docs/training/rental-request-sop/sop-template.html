1. Overview

The rental request form is a single mobile-friendly page where a technician asks Fleet for a rental vehicle — either a new rental (van is down, or a new hire has no van yet) or an extension (more time on a rental they already hold). It replaces calling Holman.

  • One permanent link: https://SHS-Nexus.replit.app/rental-request — no login, no app. It works from a phone standing next to a dead van. The technician proves who they are by entering their LDAP; the form checks it against the technician roster.
  • How technicians get the link: it can be posted/shared anywhere (it is permanent), the weekly extension-reminder text includes it, and every Fleet decision text (approval, send-back, denial) includes it where relevant.
  • One request at a time: the form refuses a second request while one is already open, and allows one filed request per day. This is deliberate — it keeps Fleet working a single ticket per technician.
  • Nothing is booked by the form itself. Submitting creates a request for Fleet to review. The technician is told the decision by text.

2. Technician walkthrough — requesting a NEW rental

1
Open the link and enter your LDAP. Type your LDAP (e.g. JSMITH1) and press Start. If the LDAP is not on the roster the form says so — check spelling, or contact Fleet if you just started.
Fig. 1 — The landing screen. LDAP only; no password.
2
Confirm your identity. The form shows what Fleet has on record — name, truck, district, state, mobile. If it is right, tap Correct. If anything is wrong, tap Something's wrong and fix the truck number or mobile number (10 digits), or explain in the box. The mobile number matters most — every decision arrives by text at this number.
Fig. 2 — Identity check + request type choice.
Fig. 3 — "Something's wrong": edit truck / mobile, or explain.
3
Pick what you need. The form pre-selects based on Fleet's records (if records show you already hold a rental, it defaults to Extension). You can override it — records can lag — but the form will ask for one line explaining why.
4
Answer the questions. The table below lists every question and what a good answer looks like. Fig. 4 shows a fully completed example.

3. Technician walkthrough — requesting an EXTENSION

An extension is more time on the rental you already have — never a different vehicle. Policy requires an extension request every 7 days while you hold a rental; the automated Fleet reminder text also links here. Steps 1–2 (LDAP + identity) are identical; the form then shows the rental Fleet believes you hold and asks five questions about the repair.

QuestionWhat is expected
Your current rental (shown, not asked)Vehicle, vendor, start date, days so far, extensions so far, location — from Fleet's records. If this is not the rental you hold, say so in the first answer box.
What is the current status of your van's repair?Where the van is and what state it is in — e.g. "Still at the shop, waiting on a transmission part."
When did you last speak with the shop?A date. Fleet expects technicians to be checking on their own van — "last week" answers get called.
What did the shop say?Their actual words — e.g. "waiting on a transmission part, due Thursday."
When does the shop expect the van to be done? (optional)Date, if the shop gave one.
Roughly how much longer do you need the rental?Plain estimate — "about one more week."
AcknowledgementsThe full set again. Extensions re-sign every term, every week — that is deliberate.
Fig. 5 — A completed extension request, showing the current-rental card and repair-status answers.
After submit
"Request received" plus "Keep the rental until you hear from us." The technician keeps driving the rental — an extension request is never a reason to return it.

5. Fleet staff — reviewing and answering requests

1
Work from the Rental Requests board (Rental Reduction → Rental Requests). The funnel at the top shows form traffic; the tabs split New requests from Extensions. Each row carries the engine's recommendation (APPROVE DENY DEFER REVIEW), the net-$/day economics, and the rule that fired. Extensions always arrive as REVIEW — a person decides every extension.
Fig. 6 — The Rental Requests board: funnel, KPI cards, and the request list with engine recommendations.
2
Open the request drawer. Clicking a row shows everything the technician answered, the profitability factors behind the recommendation, and the decision buttons. The engine recommends; you decide.
Fig. 7 — The decision drawer: request details, profitability factors, and APPROVE / DENY / DEFER.

Approving a NEW rental

  • Pickup date defaults intelligently: a request approved on Friday defaults to Monday pickup (no weekend rental days we pay for while the tech is off). Override it if the tech works Saturday.
  • The approval text is editable. The standard text reads: Sears Fleet: your rental request is approved. We are booking the reservation for pickup {{pickup_day}} {{pickup_date}} and will text you the confirmation number and branch. The Monday variant adds the Uber-home offer. What is in the box is exactly what sends — edit it when the situation needs it.
  • Booking is automatic after approval. The system quotes and reserves with Enterprise (20–30 seconds); the technician then gets a second text with the confirmation number, the actual branch address/phone, and instructions (bring driver's license, billing is direct to Sears, decline insurance and upgrades).
  • If booking fails, the drawer shows the failure — retry from there; do not book manually unless the drawer says to.

Approving an EXTENSION

  • The drawer asks for the reservation / RA number (required) and extra days (1–30, defaults to 7). That is the whole action — approving an extension never books a new vehicle.
  • The technician gets a fixed text: Sears Fleet: your rental extension is approved. We are arranging the extra time with Enterprise — keep the rental, no action needed unless we text you.
  • On first approval the system emails Enterprise (North Central Account Support) with the renter, RA number and additional days — Howard Anderson and Tyler Morgan are always CC'd. Re-approving does not duplicate the email; use the Resend button if Enterprise asks again.

Other decisions

DecisionWhat happens
DENYTech is texted: Sears Fleet: your request was not approved… Reply to this message if your situation has changed. Denials are recorded with the reason — they are the number that justifies this program.
DEFERSame-day / wait-on-it cases. The request stays open, waiting on a person.
SEND BACK (RETURN)Use when the request is missing something (wrong shop phone, no Enterprise branch…). The tech is texted exactly what is missing plus the link; their earlier answers are saved and only the gaps are asked.
Timing
Every decision text goes to the mobile number the technician confirmed at the top of the form. Decide during working hours when possible — the tech may need to act (pick up the rental, call the shop) on what you send.

6. Status vocabulary reference

StatusMeaning
pendingWaiting on Fleet — nobody has decided yet.
approvedDecision made; a new rental may still be booking with Enterprise.
bookedEnterprise reservation confirmed — terminal for the request; the decide buttons refuse it.
deniedRefused, with reason; tech notified by text.
deferredParked for a person to revisit.
returnedSent back to the technician for missing information.
Booking: in progress / failed / attentionThe automatic Enterprise booking after approval — failures surface in the drawer for retry.
