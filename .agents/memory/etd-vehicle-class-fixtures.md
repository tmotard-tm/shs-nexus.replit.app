# ETD vehicle-class parity fixtures

**Rule:** After ANY change to `etd-runner/scripts/vehicle_class.py` or `server/vrm/etd/vehicle-class.ts`, regenerate the differential fixtures (`etd-runner/.venv/bin/python tests/fixtures/etd-surgery/generate.py`) and run `tests/etd-surgery-differential.test.ts`. If the "tables themselves are the same" case fails, suspect a STALE FIXTURE before suspecting the port.

**Why:** The fixtures are committed JSON regenerated by hand. In Aug 2026 they sat stale across two behavior changes (the sedan-ladder smallest-first flip and the plain-sedan escalation), so the differential suite was red for the wrong reasons and, worse, a stale fixture *passed* the `same_*` cases while hiding a real divergence: Python's `choose_same_vehicle` gained ETD-first class reading (`etd_class_for`) that the TS `chooseSameVehicle` never received. Stale fixtures can fake parity in both directions.

**How to apply:**
- A `same_*` note mismatch of the form "no ETD class at this branch names …" = the TS port still lacks Python's ETD-first reading, not a fixture problem.
- The differential suite is not wired into any configured workflow, so red states sit unnoticed — run it manually when touching either file.
- Baseline discipline: before blaming your change, stash and run against the pristine tree to separate pre-existing failures from new ones.
