Forward-looking risk surface for the Fleet Management module. These are the gaps that are NOT obvious without deep cross-file tracing (the rest are derivable from code):

**Re-verified 2026-07-25 PM (third premortem, post skip-path hardening):** Explorer verdicts were triple-checked by hand — three "fixed" claims were WRONG. Current truth: swallow asymmetry (A) STILL OPEN (createSubmission catch returns success:true, holman-assignment-update-service ~300); assign/unassign routes STILL requireAuth-only; op-events retry STILL dead in prod (only dev-only checkAndRunSync + manual admin route; dispatcher /roster-sync has no drain). FIXED since premortem 2: UI now invalidates queries after assign/unassign; fence-supersede sweep lifts stale district fences; district frozen for ALL trucks in sync. NEW findings: (1) **the entire Holman verify pipeline is in-process timers on autoscale** — scheduleVerification = setTimeout chains (holman-submission-service ~551-628), backstop pollPendingSubmissions = 90s setInterval armed at boot (index.ts ~422) — verification is bursty/degraded in prod, amplifying frozen-fence, optimistic-cache-rollback, and pending-row staleness; (2) **swallow asymmetry now defeats the new skip gate**: a 202 whose submission row failed to persist is invisible to both the healer AND the pre-check's pending/processing gate → a later assign can skipVerified while the orphaned queued op lands after (the exact divergence the gate was built to stop); (3) bulk-fix 'conflict' branch + fleet-alignment conflict dialog are dead for unassign (now skipped/crossTruck, intended) so a WRONG crossTruck call from a stale TPMS read auto-proceeds with no signal — wants an audit row; (4) bulk/reconciliation flows now do N serial live pre-check calls (8s-capped each) — latency amplification, want a skipPreCheck flag; (5) no metric separates verified-skip vs fail-open. Architect-endorsed ranked order: fix A (return success:false on persist failure, mirror district route) → ONE dispatcher cron endpoint draining pollPendingSubmissions()+retryFailedOperationEvents() (closes op-events too) → sync-clobber local-write-newer guard + failed-op cache eviction → crossTruck audit row + bulk pre-check bypass → idempotency key (demoted; cross-instance lock is an atomic conditional UPDATE) → permissions decision.

**Re-verified 2026-07-25 (second premortem):** items below marked OPEN were confirmed still present in current code; the write-fence stale-pin issue is FIXED (live-confirmed supersede release only — see holman-write-fence-supersede.md). New nuances found: (a) sync clobber of tech fields now has a fence exception (fenced trucks preserve tech fields), but non-fenced trucks are still clobberable by an in-flight pull racing a manual op; (b) assign/unassign routes are requireAuth-only with NO role/permission check, while district update checks `updateDistricts` — an unreviewed asymmetry; (c) the UI deliberately skips query invalidation after assign/unassign (optimistic patch only), so a Holman-side silent drop leaves the card wrong until a sync/hard refresh; (d) mismatch list has a 15-min server cache (Force Rebuild bypasses; fence sweep drops it on lift). Ranked hardening order given to user: surface submission-persist failure (kill the swallow asymmetry) → wire op-events retry into Fleet-Dispatcher → guard tech fields from sync clobber via local-write-newer check → idempotency key → stuck-op visibility → permission decision.

- **Downstream-applied-but-local-failed divergence**: cross-system writes (TPMS/Holman/AMS) fan out in parallel BEFORE the atomic `writeThroughCaches` DB tx. If that tx throws (e.g. a real value over a `varchar(50)` limit — narrowly the TPMS / tech-profile ID fields, since the log/holman/ams cache cols are `text`), the external systems are already changed but Nexus records the op as failed. There is no reconciliation queue to heal it.
- **Asymmetry — district SURFACES a submission-persist failure, assign/unassign SWALLOWS it.** The district route returns failure if the `holman_submissions` verify record can't persist; the assign/unassign path swallows that same failure → Holman can be marked `pending` with NO verifier and NO submissionDbId, so it never gets confirmed and never expires. This asymmetry is the single most important non-obvious finding.
- **No idempotency key on Holman submissions.** Duplicate clicks / retries enqueue multiple 202s; the verifier matches by truck/op/time-window, so duplicates can confirm against the wrong submission.
- **Sync clobbers assignment fields; only `district` is frozen.** Post-response background `updateCache` (`Promise.resolve().then(...)`) + `onConflictDoUpdate` can overwrite `holman_tech_assigned` / `tpms_assigned_tech_id` that a concurrent user op just set. District is the only field protected via `sql\`${cache.district}\``.
- **Frozen-district deadlock**: cache.district stays frozen until `verifyFromFleetData` unlocks it; if the verify record never persists/matches, district is stuck at the old value forever (no audit / unfreeze path).
- **TPMS stale sweep does not mirror back to `holman_vehicles_cache`.** The 4h/50-row sweep updates/evicts `tpms_cached_assignments` only; the fleet cache the UI reads can stay stale. Plus ~25% of tpms rows have empty `raw_response` and can't be enriched.
- **propagateStatusToFleetLog only flips the log status** — it does NOT roll back the optimistic Holman cache written on `pending`. A later `failed` leaves the cache still showing the tech.
- **Lock is target-row-only + 2-min.** Auto-unassign/displacement touches the old/displaced truck without separately locking it; a slow Holman op can outlive the 2-min lease.
- **PRODUCTION runs almost none of the recurring sync polls.** `startSyncScheduler()` only arms `setInterval(checkAndRunSync)` when `isDevelopment` (NODE_ENV !== 'production'); the prod branch logs "daily sync setInterval disabled". Since `checkAndRunSync` is the ONLY caller of the TPMS watermark poll, AMS watermark poll, TPMS 4h stale sweep, op-events retry, and 12h enrichment, NONE of those run in a published deployment. Only the separation poll + notification-backfill intervals survive in prod; daily Tech-Data/Assigned schedulers self-schedule separately so the TPMS *snapshot* still refreshes. Consequence: in prod, assignment/district changes made directly in TPMS/AMS (outside Nexus) are reconciled only via the daily schedulers + on-demand per-vehicle lookups, NOT every 15 min; and failed AMS assign/unassign ops queued in op_events are never auto-retried. Likely an autoscale-safety choice (setInterval is unreliable across autoscale instances) — confirm deployment type before treating as a bug.
- **Snowflake private-key material logged at startup** — REMEDIATED (verified June 2026): `snowflake-service.ts` no longer prints any `privateKey.substring/slice`. Keep an eye out for regressions, but this is no longer an active leak.
- **AMS current-location enrichment on the fleet cold path — HARDENED (June 2026).** Any AMS full-fleet sweep (`buildAmsFullFleetCache`, paginating 20×500 `/vehicles` pages) that sits on a request-awaited path is a cold-start proxy-timeout risk: the merge that added per-card Current Location wired it inline+unbounded into `enrichWithAMSData` and the first `/api/holman/fleet-vehicles` hit ~132s (autoscale proxy ~60s). Mitigation now in place, and the **durable rule** for this surface: (1) the request-path enrich call is bounded + fail-open (Promise.race ~8s → empty current-location; the UI falls back to the registered Holman location) — and the underlying module-level build promise keeps running so the next request gets a warm cache; (2) every AMS page fetch uses a per-page AbortController timeout (25s) + 1 retry, mirroring `buildAmsTruckStatusMap`, so one stalled page can't pin the shared build promise forever; (3) an incomplete (gave-up-early) sweep is cached but with a SHORT TTL (~10min, vs 1h) so a transient AMS hiccup self-heals instead of masking missing data for an hour; (4) both AMS caches (truck-status + full-fleet) are pre-warmed at startup via `setImmediate`, chained (truck-status THEN full-fleet) because both paginate the SAME `/vehicles` endpoint — running them concurrently doubles AMS load. **Why:** restores the pre-merge cold-start risk profile while keeping the Current Location feature. **Separate, still-open finding:** the `/api/ams/truck-status-map` pills endpoint can still 502/503 during heavy cold start (its own build vs proxy window) — that path was NOT changed here.

**Why:** the user ran a pre-mortem on Fleet Management (sync / district / assign-unassign) to prioritize hardening.
**How to apply:** when touching fleet ops, prioritize Holman verifier durability + idempotency, protect locally-updated assignment fields from sync clobber, and add stuck-operation / district / TPMS-drift visibility before adding features.
