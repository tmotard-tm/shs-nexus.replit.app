2. Backend Service: server/create-offboarding-tasks-service.ts
Create this file (or replace if it exists). This is a gap-check service that ensures every offboarding technician has all 5 required task types created.

The 5 task types:

ntao_stop_replenishment_day0 — Department: NTAO, workflow step 1
tools_recover_equipment_day0 — Department: Assets Management, workflow step 2
fleet_initial_coordination_day0 — Department: FLEET, workflow step 3
inventory_remove_tpms_day0 — Department: Inventory Control, workflow step 4
phone_recover_device_day0 — Department: Inventory Control (subtask: Phone Recovery), workflow step 5
Core logic of createOffboardingQueueTasks(triggeredBy):

Create a sync log entry with type create_offboarding_tasks, status running
Query all existing queue_items where workflowType='offboarding' and workflowId IS NOT NULL — build a Map<workflowId, Set<stepType>> of existing tasks
From those same items, extract tech info from each workflow's first item's JSON data field (fields: data.technician.techName, data.technician.techRacfid as enterpriseId, data.technician.employeeId, data.vehicle.vehicleNumber as truckNumber, data.technician.lastDayWorked, data.technician.effectiveDate, data.technician.district, data.technician.planningArea, data.technician.contactNumber, data.technician.personalEmail, data.technician.separationCategory, data.technician.jobTitle, data.vehicle.fleetPickupAddress)
Query termed_techs table for rows with offboardingTaskCreated=false and non-null employeeId — add any new techs not already in the workflow map with workflowId format termed-{employeeId}
If Snowflake is configured (isSnowflakeConfigured()), refresh termed_techs via getSnowflakeSyncService().syncTermedTechs() and re-check for new rows. Wrap in try/catch — Snowflake failure is non-fatal.
Enrich techs missing truck numbers from tpms_cached_assignments table (match by enterpriseId)
For each workflow, iterate the 5 task types. Skip any that already exist in the step set. For missing ones, create the task via the appropriate storage method:
NTAO → storage.createNTAOQueueItem()
Assets Management → storage.createAssetsQueueItem() — also apply BYOV logic: call getInitialToolsTaskStatus(truckNumber) to set blockedActions, fleetRoutingDecision, routingReceivedAt. Set assignedTo to TOOLS_OWNER.id.
Fleet → storage.createFleetQueueItem()
Inventory Control (both inventory and phone) → storage.createInventoryQueueItem()
BYOV detection: truck number starts with "88". TLT detection: jobTitle exactly equals "Team Lead Technician".
Phone tasks get extra fields: phoneNumber from tech's contactNumber, phoneRecoveryStage: 'initiation', phoneContactHistory: []
All tasks created with: workflowType: 'offboarding', status: 'pending', priority: 'high', requesterId: 'system', and a JSON data field containing { workflowType: 'offboarding_sequence', step: taskType, subtask, phase: 'day0', isDay0Task: true, source: 'create_offboarding_tasks', syncedAt, technician: {...}, vehicle: {...}, instructions: [...] }
After creating tasks for a termed-* workflow, update the termed_techs row: set offboardingTaskCreated=true, offboardingTaskId=workflowId, processedAt=now
Update the sync log with completion stats
Return { success, techsProcessed, tasksCreated, tasksSkipped, errors }
Also export checkOffboardingDuplicates(): Query all offboarding queue_items, group by enterpriseId::taskType::workflowId, return any groups with count > 1.

Each task type has specific instructions arrays:

NTAO: "Place a shipping hold to prevent future shipments", "Cancel any pending orders for this Employee", "Cancel all backorders associated with the vehicle", "Remove Employee from automatic replenishment system", "Update truck status in NTAO system", "Complete Day 0 task"
Assets/Tools: "Contact Employee immediately to arrange equipment return", "Recover company phone and verify it's company-issued", "Collect any tablets, mobile hotspots, or other devices", "Retrieve company credit cards", "Check for accessories (chargers, cases, cables)", "Wipe all device data per security protocol", "Update asset management system with returned items", "Complete Day 0 task"
Fleet: "Contact Employee immediately to notify of offboarding process", "Arrange preliminary meeting/call to discuss vehicle handover", "Obtain current vehicle location and condition information", "Begin coordination with Employee for vehicle retrieval timing", "Assess any immediate vehicle security or safety concerns", "Document initial vehicle status and location", "Complete Day 0 task"
Inventory: "Access TPMS immediately", "Locate vehicle assignment for terminated Employee", "Remove vehicle from TPMS assignment", "Update vehicle status to unassigned/pending-offboard", "Clear and cancel any pending parts orders", "Update inventory system to stop automatic replenishment", "Complete Day 0 task"
Phone Recovery: "Contact Employee to arrange phone return", "Verify phone is company-issued device", "Create shipping label if needed", "Track phone recovery progress", "Wipe device data upon receipt", "Update phone inventory status"
3. API Routes (add to server/routes.ts)
Add a section // ===== Unified Offboarding Queue API ===== with these components:

Helper: classifyOffboardingQueue(step, department) — returns a queue key string:

phone_recover_device_day0 → 'phone'
ntao_stop_replenishment_day0 OR dept NTAO → 'ntao'
tools_recover_equipment_day0 OR dept ASSETS MANAGEMENT or ASSETS → 'assets'
fleet_initial_coordination_day0 OR dept FLEET → 'fleet'
inventory_remove_tpms_day0 OR dept INVENTORY CONTROL or INVENTORY → 'inventory'
Otherwise → 'unknown'
Helper: hasOffboardingAccess(user) — developer/admin always true. For agents: must have at least one queue access (ntao/assets/fleet/inventory via existing hasQueueAccess), AND sidebar.queues.offboardingQueue must not be explicitly false in role permissions.

Endpoints:

GET /api/unified-offboarding/techs (requireAuth):

Check hasOffboardingAccess
Query all queue_items where workflowType='offboarding' and workflowId IS NOT NULL
Group items by workflowId into a Map
For each workflow group: extract tech info from first item's JSON data, compute daysOpen from separationDate, detect isByov (truck starts with "88") and isTlt (jobTitle === "Team Lead Technician"), build queueStatuses record (5 keys: ntao/assets/fleet/inventory/phone, each with {status, id}, defaulting to {status:'missing', id:null}), compute hasEscalation (priority==='critical' OR status==='pending' && daysOpen > 7), detect hasRental from data
Also query termed_techs table — add any techs not already represented (by enterpriseId match) with all-missing queue statuses and workflowId termed-{employeeId}
Sort all techs by separationDate descending
Compute queueBreakdown: for each queue, count pending/in_progress/completed/missing across all techs
Return { techs: [...], summary: { totalTechs, escalated, avgDaysOpen, completionPct, queueBreakdown } }
GET /api/unified-offboarding/tech/:workflowId (requireAuth):

Check hasOffboardingAccess
Query queue_items for matching workflowId and workflowType='offboarding'
If no items found and workflowId starts with termed-, lookup in termed_techs by employeeId and return basic info with empty tasks object
Build a tasks record keyed by queue key (phone/ntao/assets/fleet/inventory), each containing: id, status, priority, assignedTo, department, notes, workflowStep, createdAt, startedAt, completedAt, isByov, isTlt, vehicleType, fleetRoutingDecision, routingReceivedAt, blockedActions, all 6 task checklist booleans, all phone recovery fields, and the parsed data object
Return full tech detail with contact info and tasks
PATCH /api/unified-offboarding/task/:taskId (requireAuth):

Check hasOffboardingAccess, verify task exists and is workflowType='offboarding'
Whitelist allowed fields: status, notes, assignedTo, priority, taskToolsReturn, taskIphoneReturn, taskDisconnectedLine, taskDisconnectedMPayment, taskCloseSegnoOrders, taskCreateShippingLabel, toolAuditNotificationSent, carrier, fleetRoutingDecision, phoneContactMethod, phoneShippingLabelSent, phoneTrackingNumber, phonePhysicalCondition, phoneConditionNotes, phoneDataWipeCompleted, phoneWipeMethod, phoneReprovisionCompleted, phoneRecoveryStage, phoneWrittenOff, phoneServiceReinstated
Auto-set startedAt when status changes to in_progress, completedAt when status changes to completed, toolAuditNotificationSentAt when toolAuditNotificationSent is set
Always set updatedAt = new Date()
Call storage.updateQueueItem(taskId, filteredUpdates)
POST /api/unified-offboarding/task/:taskId/contact-log (requireAuth):

Check hasOffboardingAccess, verify task exists and is offboarding
Read existing phoneContactHistory array (or initialize empty)
Push new entry: { method, notes, contactedBy: req.body.contactedBy || req.user.id, timestamp: new Date().toISOString() }
Update task with new history array and phoneContactMethod
GET /api/unified-offboarding/admin/duplicate-check (requireAuth, admin/developer only):

Import and call checkOffboardingDuplicates() from the service
POST /api/unified-offboarding/admin/run-task-creation (requireAuth, admin/developer only):

Import and call createOffboardingQueueTasks('manual') from the service
