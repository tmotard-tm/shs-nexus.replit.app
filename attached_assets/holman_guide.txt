Introduction
Holman’s API Developer Guide provides you with an overview on development procedures to integrate various data endpoints with
your in-house platforms. Specifically, it will outline how to connect, retrieve (Basic & Custom Query endpoints), and send (Submit
endpoints) data via Holman’s API.

Holman’s API solution is designed to be flexible and versatile. It allows clients to query and submit raw data, which can then be
integrated with any software that supports API interactions. Essentially, our API provides the data, and the integration with specific
software would be handled on the client’s end, ensuring compatibility with their existing systems.

Holman’s Application Programming Interface (API) was designed using principles of RESTful APIs.

Holman’s API connection currently offers scalable data for the endpoints listed in the Table of Contents.

Here are some common fleet functions you can automate via our API solution:
    ✓ Add/edit/remove Contacts via the Contacts endpoint directly from your HRIM system.
    ✓ Store contact-based information such as reporting hierarchy, cost centers, hire date, etc.
    ✓ Automatically qualify contacts for Holman’s Safety program to issue them relevant safety modules, training, motor vehicle
        record checks, etc.
    ✓ Grant contacts immediate access to the Holman’s Insights Mobile App where they can report mileage, request roadside
        assistance, find nearby vendors, etc.
             o For more information about our Holman Insights Mobile App:
                   Fleet Manager & Driver Canada
                   Fleet Manager & Driver US
    ✓ Add/edit/remove vehicles from your inventory via the Vehicles endpoint.
    ✓ Assign contacts to vehicles and maintain inventory with other vehicle-based elements such as project GL codes, location,
        usage identifiers, etc.
    ✓ Generate WEX fuel PINs (US clients only).
    ✓ Automatically qualify drivers for Holman’s Fringe/Taxable Benefits program so that they can begin reporting their mileage.
    ✓ Load fuel, maintenance and accident transaction history that occurred outside of Holman’s programs to Holman Insights so
        that it is available for vehicle-level history and comprehensive TCO fleet reporting.
    ✓ Provide odometer and engine hour readings to be incorporated into Holman’s algorithms where they are validated and used
        for analytics such as preventive maintenance reminders.
    ✓ Create user IDs for fleet administrators who should have access to Holman Insights and the Fleet Manager App.
    ✓ Ability to add/edit/delete maintenance and ordering approvers.
    ✓ Extract data on a variety of endpoints for your own internal reporting and analytics.

Here are some features we are actively working on to serve you better:
    ✓ A user registration process that will give clients greater control over their API users.
    ✓ Greater historic data reporting periods.
    ✓ Third party access so that your other fleet partners can exchange data with us easily on your behalf.
    ✓ New endpoints for:
            o Holman Safety program and Driver Scorecard information to monitor driver risk and compliance.
            o EV data to help you work towards your sustainability goals.
            o Licensing and Remarketing to be able to monitor statuses and get more in-depth reporting.
    ✓ Data connectors to PowerBI, Excel, Business Objects and Tableau.
    ✓ API Runners to help you manage errors and exceptions more easily.
    ✓ API code library that will make it easier for a clients’ development team to integrate with Holman.

If you have any feedback about our API offering we would love to hear it here as we are always looking for ways to improve this
experience for you!

Important Concepts
Please familiarize yourself with the below universal concepts which you will encounter throughout the documentation as it
will impact how you make your calls and interpret the results.

QUERY and SUBMIT Actions
As per standard REST API conventions:
o Basic-query endpoints use GET method to return information.
o Custom-query endpoints (because they require a body in the API call) use POST method to return information.
    o We allow for selecting properties, filtering, pagination and delta data retrieval.
    o Examples of how to structure the custom requests are provided with each of the endpoints.
o Submit endpoints use POST method to send information.

ENDPOINT URL
URLs are provided within this document for each endpoint. The URL is to be entered into your User Interface of choice
that you will use to make the API calls, not your web browser.

HEADER
x-correlation-id
Holman can use this to trace your request through our system. If you get an error with a call and need Holman to help
troubleshoot, please engage Holman's Client Technology team for support via this form Request for Technical API
Support (2.0). A member of Holman’s Client Technology team will contact you to help resolve your issue. This form will
require you to supply at minimum the environment you are working in (QA/Prod) and this x-correlation-id.

RESPONSE BODY
For Basic and Custom query endpoints, you will return the following:
totalCount – total number of records from the call
pageInfo – the node that contains the following
        pageNumber – current page number
        pageSize – number of records on the current page
        totalPages – total number of pages
        lastChangeRecordId – if you want delta data, you need to specify this in the request

lesseeCode
A 4-character alphanumeric code that identifies the client in Holman’s system. Clients can have more than one
lesseeCode for their fleet. LesseeCode is a critical component to each endpoint as it is used to help validate your calls.
Your Holman Representative can provide this information to you.

VEHICLE IDENTIFIERS
Each asset in Holman’s database is identified by a holmanVehicleNumber. Some clients also utilize a
clientVehicleNumber for their own unique numbering sequence.
holmanVehicleNumber and clientVehicleNumber are unique within a lesseeCode but not across lesseeCode. A vehicle’s
vin number is also unique within a lesseeCode but not across lesseeCode. Together with the lesseeCode, these
identifiers are unique to the asset. This is why on vehicle-based endpoints, we require a combination of any of the below
to identify the record:
          1. lesseeCode & holmanVehicleNumber
          2. lesseeCode & clientVehicleNumber
          3. lesseeCode & vin

If you do not know the lesseeCode, holmanVehicleNumber, clientVehicleNumber or vin, you can use the ‘QUERY Vehicle
Data (Basic & Custom) Endpoints’ to retrieve this information and return it in any SUBMIT calls where it is required.

You can only submit one of the three identifying combinations for a given record. For example if you submit lesseeCode &

holmanVehicleNumber, then if lesseeCode & clientVehicleNumber or lesseeCode & vin are also provided, the call will fail
because we will not know exactly which identifier you would like us to use to verify the record. Specifically, you will see
error: "Vehicle identifiers are mutually exclusive. Only one field may be populated: `holmanVehicleNumber`,
`clientVehicleNumber`, or `vin`."

CLIENT-DEFINED CUSTOM FIELDS
Holman offers clients a variety of client-defined fields they can use to store information unique to their fleet and contacts.
Information may include cost centers, reporting managers, business units, etc. Each client’s use of these fields is unique.
Your Holman Representative can provide you information on how the client’s terminology maps to Holman’s fields and
how that data is maintained. On the ‘SUBMIT Add new or update existing Vehicles Endpoint’ for example, if the data
passed exceeds the allowed character limit, an error will be generated in the Status endpoint.

SUBMIT Add new or update existing
Contacts Endpoint
This endpoint uses POST method to add and update your fleet contact details into Holman systems. These endpoints are
commonly used for contact information (i.e. contactLastName, contactAddressLine1), employment dates (i.e.
contactHireDate), and client-defined fields (i.e. contactClientData1, contactAuxData1).

There are different required fields depending on if you are adding a new contact to the database or updating an existing
contact.

Please consult your Holman Representative to understand how this data needs to be maintained, especially for the client-
defined fields. The data entered via this endpoint can affect reporting and program qualifications.

Field Requirement “Add” refers to adding a new contact to Holman’s system.

Field Requirement “Update” refers to updating the data for an existing contact in Holman’s system.

Field Requirement “Safety” refers to when you are enrolling/terminating the contact from the Holman Safety program.

Field Requirement “Asset Assign” refers to when you are assigning a contact to an asset in the inventory. In this scenario,
you must identify the asset record with one of the following combinations of unique identifiers. If you don’t have this
information in your database, you can retrieve it from the VEHICLE – BASIC or CUSTOM QUERRY endpoint.

        1. lesseeCode & holmanVehicleNumber
        2. lesseeCode & clientVehicleNumber
        3. lesseeCode & vin
        4. lesseeCode & licensePlate
