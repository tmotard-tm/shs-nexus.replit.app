Publish checklist (ready to use once package.json is verified)
Step 1 — Pre-publish sanity
Before touching the Publish button:

Git working tree is clean. git status shows nothing uncommitted.
No stale processes holding port 5000 (if you've been running npm run dev, stop it).
Dev server has started cleanly at least once since the commits. Watch for [G8] skipped (NODE_ENV=development) in the boot log.
npm run build executes locally without error. This pre-flights the new build chain (deploy:snapshot && G3 gate && vite && esbuild && deploy:record) without actually publishing. If any stage fails here, it would fail in the real deploy too — better to catch it now.

Step 2 — Hit Publish
In Replit → Deployments → Publish. Immediately switch to the Deployments → Logs tab and watch for:

[G8] OK — prod DB host verified. — proves G8 is live and prod host matches expected. If you see [G8] FATAL — prod DATABASE_URL host mismatch instead, the deploy will not start and you need to stop and reconcile what host prod is actually using.
serving on port <port> — the existing server-started log.
[G4] ... — integrity check output. Expect either [G4] OK (row counts within tolerance) or [G4] No baseline snapshot found in object storage. First deploy after G2 install establishes the baseline going forward. — the latter is expected on this first deploy.

If you see [G8] FATAL at any point, the deploy has refused to start and is doing exactly what it's supposed to. Send the exact log line here and we'll diagnose.
Step 3 — Post-publish bundle verification
This is the standard from the deployment gap. Run from any shell:
curl -s https://shs-nexus.replit.app/vehicle-rental-management/rental-repair-tracker > /tmp/prod.html
BUNDLE=$(grep -oE '/assets/index-[A-Za-z0-9_-]+\.js' /tmp/prod.html | head -1)
echo "Bundle: $BUNDLE"
curl -s "https://shs-nexus.replit.app$BUNDLE" > /tmp/prod.js
echo "--- Grep results ---"
echo "Last Action:  $(grep -o 'Last Action' /tmp/prod.js | wc -l)  (expected: 0)"
echo "StagePill:    $(grep -o 'StagePill' /tmp/prod.js | wc -l)  (expected: ≥1)"
echo "AmsDrawerTab: $(grep -o 'AmsDrawerTab' /tmp/prod.js | wc -l)  (expected: ≥1)"
echo "Action Needed:$(grep -o 'Action Needed' /tmp/prod.js | wc -l)  (expected: ≥1)"
echo "In Progress:  $(grep -o 'In Progress' /tmp/prod.js | wc -l)  (expected: ≥1)"
echo "Archive:      $(grep -o 'Archive' /tmp/prod.js | wc -l)  (expected: ≥1)"
echo "Bundle hash:  should NOT be Cpts0mCR (the stale bundle before closeout)"
Pass criteria: Last Action = 0, all others ≥ 1, bundle hash is new (not Cpts0mCR). If any check fails, the deployment gap is back and we stop.
Step 4 — Production UI walkthrough
Open https://shs-nexus.replit.app/vehicle-rental-management/rental-repair-tracker in a hard-refresh session (Ctrl+Shift+R). Spot-check:

Three section headers visible: Action Needed, In Progress, Completed.
Stage column showing pills like Needs Tech Call, In Repair.
Punch column populated with Punched In/Out/Unknown + timestamps (not all "No data" like the old prod).
Last Action column is gone.
Open one row's side drawer — Details tab, Punch History tab, AMS tab.
On any row with route_cleared=Yes, confirm Van Status shows the physical state (not "Route Canceled").
Archive / restore functionality on a test row.

If all seven pass: guardrails + closeout are both live and verified. We're done with this phase.
Step 5 — First real G2 snapshot lands
On the first production deploy, G2 writes the baseline snapshot to Object Storage at guardrails/ (not guardrails/dryrun/). From that point forward, every subsequent publish will have G4 integrity-check against a real baseline, and you'll get actual row-count comparisons instead of the "no baseline" fail-open.
