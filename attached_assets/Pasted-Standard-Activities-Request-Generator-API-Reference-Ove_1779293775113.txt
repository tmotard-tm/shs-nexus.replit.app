Standard Activities Request Generator — API Reference
Overview
This API allows external systems to submit Availability Requests (Make Unavailable / Quick Return) and standard OPS activity scheduling requests programmatically.
All endpoints are live at the production deployment URL. No additional setup is required beyond the base URL and API key.
________________________________________
Connection Details
Item	Value
Base URL	Your production deployment URL (e.g. https://your-app.replit.app)
Auth Header	Authorization: Bearer <SUBMISSION_API_KEY>
Content-Type	application/json
All requests must include the Authorization header. Store both values as environment secrets in your application — do not hardcode them.
________________________________________
Error Codes (All Endpoints)
Code	Meaning
400	Missing required field or invalid value
401	No API key provided
403	Invalid API key
404	Referenced resource not found
409	Duplicate project name, or a return has already been filed
500	Internal server error

Endpoint 1 — Availability Request
POST <BASE_URL>/api/availability-request
Handles both Make Unavailable (tech removal) and Quick Return (Make Available). Same URL — the availabilityType field determines which flow runs.
Both flows bypass admin review and go directly to awaiting_dca status. The DCA team is notified automatically.
________________________________________
1A — Make Unavailable
Use when a tech is denied a rental or otherwise needs to be removed from route.
Required Fields
Field	Type	Notes
techId	string	Tech enterprise ID — case insensitive
availabilityType	string	Must be "make_unavailable"
reasonCode	string	See valid values below
impactDate	string	YYYY-MM-DD — First Date Off Route
Optional Fields
Field	Type	Notes
submittedBy	string	Label shown in the admin queue (e.g. your system name)
submitterEmail	string	Receives confirmation email
projectNotes	string	Free text — visible to admin
unit	string	Auto-looked up from roster if omitted
Valid reasonCode Values
•	Rental Reduction
•	LP Review
•	Termination
•	WCLOA
Example Payload
{
  "techId": "A1234567",
  "availabilityType": "make_unavailable",
  "reasonCode": "Rental Reduction",
  "impactDate": "2026-05-20",
  "submittedBy": "RENTAL_SYSTEM",
  "submitterEmail": "alerts@transformco.com",
  "projectNotes": "Tech denied rental on 05/11/2026"
}
Example Response (201 Created)
{
  "id": "7a5d7077-7a71-42a3-90be-9c41903547c5",
  "projectName": "AV A1234567 - 2026-05-20",
  "status": "awaiting_dca",
  "availabilityType": "make_unavailable",
  "reasonCode": "Rental Reduction",
  "impactDate": "2026-05-20",
  "linkedReturnProjectId": null
}
Important: Save the id from the response. You will need it to submit a Quick Return for this tech.

1B — Quick Return (Make Available)
Use when the tech is getting a rental again and needs to be returned to route.
Required Fields
Field	Type	Notes
techId	string	Must match the original Make Unavailable
availabilityType	string	Must be "make_available"
impactDate	string	YYYY-MM-DD — First Date Back on Route
sourceProjectId	string	The id returned from the Make Unavailable response
Optional Fields
Field	Type	Notes
reasonCode	string	Same valid values as above
submittedBy	string	
submitterEmail	string	Receives confirmation email
Example Payload
{
  "techId": "A1234567",
  "availabilityType": "make_available",
  "reasonCode": "Rental Reduction",
  "impactDate": "2026-06-10",
  "sourceProjectId": "7a5d7077-7a71-42a3-90be-9c41903547c5",
  "submittedBy": "RENTAL_SYSTEM",
  "submitterEmail": "alerts@transformco.com"
}
Example Response (201 Created)
{
  "id": "2e1b75c1-dc78-4165-b144-96be6b6750ad",
  "projectName": "AV A1234567 - 2026-06-10",
  "status": "awaiting_dca",
  "availabilityType": "make_available",
  "impactDate": "2026-06-10",
  "linkedReturnProjectId": null
}
The server validates that the sourceProjectId exists, is a Make Unavailable request, and has no prior return already filed. A 409 is returned if a return has already been submitted.

Endpoint 2 — OPS / Standard Activities Submission
POST <BASE_URL>/api/pending-exports
Submits a standard scheduled activities request for one or more technicians.
•	If the request meets auto-approve thresholds (≤ 20 unique technicians AND ≤ 40 total scheduled hours), it is automatically approved and moves directly to the processing queue.
•	Otherwise it goes to admin review (pending_review).
________________________________________
Required Fields (Envelope)
Field	Type	Notes
projectName	string	Must be unique across all projects
submittedBy	string	RACF ID or system label
rowCount	number	Total number of rows in exportData
exportData	array	One object per scheduled event — see below
Optional Fields (Envelope)
Field	Type	Notes
submitterEmail	string	Receives approval/denial/completion emails — recommended
________________________________________
exportData Row Fields
Each entry in exportData represents one scheduled event for one technician on one date.
Required Row Fields
Field	Type	Notes
TechnicianId	string	Tech enterprise ID
ActivityType	string	Numeric activity code as a string (e.g. "38")
Date	string	YYYY-MM-DD
StartTime	string	HH:MM 24-hour format
Duration	number	Length of activity in minutes
Unit	string	District code (e.g. "MWR31")
Optional Row Fields
Send empty strings "" for any of these you don't have values for — do not omit the keys.
Field	Type	Default / Notes
LocationType	string	"None", "Home", or "Supplied"
LocationValue	string	Zip code — only used when LocationType is "Supplied"
TravelBehavior	string	"None", "Drive", or "DriveHome"
Notes	string	Free text
CheckJobs	string	"TRUE" or "FALSE"
CheckStdActs	string	"TRUE" or "FALSE"
CheckFrozen	string	"TRUE" or "FALSE"
RequestedStartDate	string	YYYY-MM-DD — start of requested scheduling window
RequestedCompletionDate	string	YYYY-MM-DD — end of requested scheduling window
RepeatOnDays	string	Comma-separated days for recurring events e.g. "Mon,Tue,Wed" — leave empty for one-time
StartTimeRequest	string	"Anytime", "Exact", or "AsSoonAsPossible"
________________________________________
