Replit Agent Prompt — Rental Repair Tracker Rebuild
Scope: Only modify the /vehicle-rental-management/rental-repair-tracker page and its supporting API/DB schema. Do not touch New Rentals, Active Rentals, Escalations, DCA Review, or Exception Cases except where a shared data source must be updated (call it out in your changelog before editing).
Goal: Convert the current flat table into a stage-driven case management view with separate note ownership, automated case off-boarding when a truck is back on road, and automatic flags for stuck cases. Preserve every existing row and every existing field value during migration.

1. Data model changes
Add the following fields to the rental repair tracker record. Migrate existing data where a value can be inferred; leave null otherwise.

denial_reason (enum: Mileage, Age, Repair Cost, Profit Threshold, Other + free-text denial_reason_detail). Backfill from the New Rentals / Profit Checker source if a join exists; otherwise leave null and expose in the edit modal.
stage (computed, read-only in UI): one of Needs Tech Call, BYOV Decision, Awaiting Rental Return, Awaiting Route Clear, In Repair, Ready for Pickup, Complete. Derived by the rules in §4.
tech_contacted_date (date), tech_contact_outcome (enum: Reached, Voicemail, No Answer, Hung Up, Refused), tech_outreach_notes (text, multi-entry timeline — append, never overwrite).
byov_offered (bool), byov_offered_date (date), byov_status (enum: Not Applicable, Offered - Considering, Enrolled, Declined), byov_decision_date (date).
rental_returned_date (date) — already tracked as bool, add the date. route_cleared_date (date).
shop_last_contacted_date (date), shop_contact_notes (text, multi-entry timeline — append, never overwrite), shop_eta_on_road (date).
assigned_tech_liaison (user), assigned_shop_liaison (user).
ams_link (url) — deep link back to the originating AMS record keyed on truck #.
closed_at (timestamp, nullable), closed_by (user, nullable).

Deprecate the single last_action free-text field: keep it read-only in the DB for audit, but stop writing to it. New writes go to tech_outreach_notes or shop_contact_notes.
2. Tech Punch Status — fix the sync
The Tech Punch Status column currently shows "No data" for every row. Diagnose and repair:

Identify the source system feeding punch status (likely the AMS or workforce system already powering New Rentals). Log the current request/response in the sync job and report back if the endpoint is returning empty, unauthorized, or mismatched keys.
Expected values: Punched In, Punched Out, On Break, No Schedule Today, Unknown. Map source values to this enum.
Sync cadence: every 15 minutes for rows in sections 1 and 2 (Action Needed, In Progress). Rows in Completed do not need to sync.
Show a small "last synced Xm ago" tooltip on the column header so we can tell at a glance if the job is stale.
If the sync cannot be fixed in this pass, surface the actual error in the cell instead of "No data" (e.g., "Auth failed", "Tech not found in source") so the failure mode is visible.

3. Page layout — split one table into three stacked, collapsible sections
Replace the current single table with three tables on the same page, in this order, each with its own header, row count, and collapse toggle.

Action Needed — expanded by default. Includes any row matching any of:

tech_contacted_date is null, OR
byov_status is null AND tech has an active rental, OR
rental_returned = No AND denied more than 2 days ago AND case is a denial, OR
route_cleared = No AND van_status = Off Road, OR
stage = Ready for Pickup and van_status has not flipped to On Road within 48 hours.


In Progress / Monitoring — everything that doesn't match Action Needed and is not Complete.
Completed (Last 14 Days) — rows where shop_status = On Road AND van_status = On Road AND (rental_returned = Yes OR byov_status = Enrolled OR denial path didn't require a rental return). Auto-move in after 24 hours at that state. Auto-archive out of the visible list after 14 days (still queryable via Export CSV and a "Show Archived" toggle).

Each section uses the same column set (see §5) so the eye doesn't have to re-learn the layout.
4. Stage computation rules (evaluated top-down, first match wins)

If shop_status = On Road AND van_status = On Road → Complete.
Else if shop_status in (On Road, Delivered to technician) AND van_status != On Road → Ready for Pickup.
Else if shop_status in (Repairing, Under repair at shop, Confirming Status, Decision Pending, Declined Repair) AND route_cleared = Yes → In Repair.
Else if rental_returned = Yes AND route_cleared != Yes → Awaiting Route Clear.
Else if byov_status in (Offered - Considering, Enrolled, Declined) AND rental_returned != Yes → Awaiting Rental Return.
Else if tech_contacted_date is not null AND byov_status is null → BYOV Decision.
Else → Needs Tech Call.

Render stage as a single colored pill in its own column, left of Shop Status.

In this order: Case (LDAP + Tech Name stacked) · Phone · District · Truck # (link to AMS via ams_link) · Denied Date + Denial Reason (stacked) · Stage · Punch Status · Shop Status · Van Status · Shop (name + phone stacked) · Shop ETA · Tech Outreach (latest note preview + date, click to expand full timeline) · Shop Contact Log (latest note preview + date, click to expand full timeline) · BYOV (status + date) · Rental Returned (Y/N + date) · Route Cleared (Y/N + date) · Assigned (Tech Liaison / Shop Liaison initials) · Supervisor (hover to reveal name + phone) · Actions (edit, close case).
Retire the single Last Action column from the visible UI.

Shop Contact Log (owned by Shop Liaison). Each entry: timestamp, author, shop ETA update (optional date picker that writes to shop_eta_on_road), free text.
